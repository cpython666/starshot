# Snipaste 选区层级规则与星镜借鉴（2026-10-29）

Windows同伴只读调查Snipaste 2.11.3 x64，主程序SHA-256为 `29aac14eca91aa8fe3d44207212078599800509d3381123fd0def34d0b19b33a`。REA 6.5.0可用，但Ghidra/IDA未配置、Hopper不支持该Windows主机，函数分析返回 `provider_unavailable`；同伴使用已有Iced 1.21.0.0按PE `.pdata` 起点解码相关函数。Mac端此次复核其交付文件，没有执行目标、安装分析引擎或触发截图。

以下都是静态调用/数据流证据，没有Snipaste运行观察。RVA加首选ImageBase `0x140000000` 得到静态VA。必要字节、偏移、指令与解析后的Qt元数据随本轮交付包的 `selection-evidence.json`、`selection-msaa-evidence.json` 提供；LOCAL-SEL编号不是REA Evidence ID。本机核对18段摘录共3,200字节、720条指令跨度、49处RIP相对引用及126处相对调用/跳转目标，记录内部一致；包内无完整EXE，不能独立证明摘录来自所声明EXE，也不把一致性复核称为重新运行反汇编引擎。

## 已证实的局部规则

- `ThreadedWindowDetector` Qt 元数据中方法4为 `queryParentRect`，方法5为 `queryChildRect`（条目RVA `0x4a96d8` / `0x4a96f0`）。信号函数 `0x32c610` / `0x32c670` 使用对应方法索引；`0x25071d–0x2507ff` 的 QObject::connectImpl 将它们分别连到 `0x254100` / `0x254330`。不是仅看到同名字符串。
- 父级函数 `0x254100` 将当前框作为参考传入检测；`0x2541fb–0x254238` 要求结果完整包含当前框、四边不完全相同，再于 `0x254252–0x254275` 比较合格候选面积，选择更小的一层。
- 辅助函数 `0x253cb0` 在当前框左/右/上/下边外一像素的中点取4个采样位置（`0x253d27–0x253d56`），在允许的外框内重新命中。`0x253ec0–0x253f0a` 先验证包含当前框，再按面积选较小者。它是几何探测，不足以证明像素边缘算法。
- `0x254330` 从对象保存的矩形层级序列向回检查；`0x2543ec` 检查包含关系，`0x25441c` 缩短序列，`0x254485` 检查鼠标仍在候选中，不适合则清除/重新检测。这是有限范围内的候选历史证据，不能扩展成通用跨窗口几何缓存。
- 之前的 MSAA 路径 `0x25dba0 → 0x25f050` 得到候选后与宿主求交、要求包含鼠标；参考框有效时还须包含参考框且不相同。`0x25f370–0x25f48a` 通过 get_accParent 找首个合格祖先；末端细框仅当被现有候选包含时才替换，不能只凭面积小取胜。
- 本轮还确认 `0x2503f4–0x25042f` 创建 QThread、创建 WindowDetector_win 并 moveToThread；说明静态上存在专用线程安排，不代表已观察其执行、终止机制或调度顺序。

现有 REA 身份证据为 `ev_ccd1d5063083d91e026578d689b33673c77af8e1eb6a256c02eefa19b6af6932`，操作是 inspect_pe_resources。它仅证明目标身份/资源结构，不为上述 Iced 调用链背书；完整记录随交付提供。

## 星镜采用的规则

初次命中仍优先可信原生控件（Windows UIA优先完整按钮而非其内部文字；macOS AX不读取角色），失败时使用最前窗口内像素/窗口候选。`captureRegionsAt` 以该初始框为起点，只将完整包住前一框的、不同尺寸的最近外层框加入候选路径；像素框可以提供中间层，但交叉框和更小的文字框不能抢进父级路径。合入后另修正近似框去重不能吞掉精确包围当前框的外层，避免候选路径丢层。

Tab 向外扩大、Shift+Tab 按同一路径缩小，两端停止，不循环跳变。第一次键盘切换冻结当前路径，避免迟到的像素分析改变反向返回目标；实际鼠标移动、重新选择或结束临时手动状态后重新计算。

这是借鉴“先包含、再比较大小、保留层级路径”的原创实现，不是 Snipaste 算法复刻。未照搬4点外探测、MSAA或其局部无预算父链；星镜已有UIA候选和像素候选即可提供第一版父层。没有证实 Snipaste 的确切按键/滚轮绑定，也没有证实它采用星镜的按钮类型优先或重叠兄弟拒绝策略，继续保留这些保护及helper限时恢复。

## 验证与限制

固定几何测试覆盖交叉框拒绝、同框去重、语义起点保持和最近外层；Windows v2原创夹具通过真实Tauri/WebView2、UIA和Rust IPC，记录两屏按钮→面板→宿主→全屏的4层路径，连续10次Tab/Shift+Tab验证端点停止和逆序返回。v2的46项是两屏各23个断言，不是46个独立应用；[Windows集成记录](windows-uia-integration.md)列出重算结果及范围。合入后的几何、Shift及查询槽修订不在原Windows二进制验收范围内，需另行重验；本机检查结果见[验证记录](verification.md)。

原生测试仅使用原创窗口和棋盘像素，手工建立Frame并指定单宿主，两屏分别运行；没有覆盖生产 `begin_capture`、真实顶层窗口枚举、同时多屏覆盖层或跨PID provider。恢复阶段重启了Starshot probe，不能证明同一进程在provider故障后恢复正常命中。Snipaste个人桌面交互未执行；未宣称完整还原窗口过滤/Z顺序、像素算法、所有重叠provider行为或鼠标事件到选区显示全链。上一轮记录的间歇启动选框缺失也不能被一次通过消除。
